> **DRAFT, derived from the code on `develop`. The owner must confirm every answer before submitting; these are legal declarations and a wrong answer can get an app removed.** Items marked **(?)** are the ones the code alone cannot settle. Both apps share one API (`apps/api`) and one Firebase project. The customer app and the driver app collect different things; columns say which.

Re-check `apps/mobile/package.json` before each release.

Shared with other users: the matched driver sees the customer's name, phone and live position; the customer sees the driver's name, phone, truck and live position (privacy policy section 4). Admins see driver documents and reports.

Not sold, no advertising or tracking (privacy policy section 2, "We do not sell personal data and do not use it for advertising").

Third parties (processors): Google (Firebase Auth, Cloud Messaging), Mapbox, hosting provider (Cloud Run per `CI.md`), Sentry (if enabled).

Encryption in transit: the app talks to the API through `EXPO_PUBLIC_API_URL` (`apps/mobile/src/api/client.ts`); the production value must be `https://` (Cloud Run URL, `CI.md`). Firebase and Mapbox use TLS. **(?)** Confirm the production URL is HTTPS and there is no cleartext exception. Encryption at rest is provided by the hosting provider's database (**(?)** confirm for the chosen host).

Account deletion: yes, in the app, Account then "Delete account" (`apps/mobile/src/features/account/DeleteAccountScreen.tsx`, route `delete-account.tsx`), which calls `DELETE /me` (`me.controller.ts` -> `AccountsService.delete`). It removes the account and profiles in both apps and cancels open jobs; most tables cascade from `users` (`onDelete: 'cascade'`). **(?)** Trip, payment and rating rows tied to requests the user was a party to: the code cascades through the requests, so they are removed too, but the privacy policy still has "[CONFIRM WHAT IS KEPT IN TRIP RECORDS AFTER DELETION]" and a "[RETENTION PERIOD]" for trip history.
